# TylerCodeverse VPS

A Railway-hosted Linux terminal branded for **TylerCodeverse**.

## What you get

- Public HTTPS browser terminal through ttyd
- No Railway variables to enter
- HTTP basic-auth login prompt on the browser terminal
- Linux shell running as `TylerDurdenDev`
- SSH server on internal port `2222`
- Python 3, Node.js/npm, Git, curl, wget, nano, vim, tmux, screen, htop and common tools
- Persistent `/data` workspace when a Railway Volume is attached
- Railway `$PORT` support

## The simple flow

```text
GitHub → Railway → Deploy → Generate Domain → Open Link → Terminal
```

After Railway generates the public domain, open it and log in:

```text
Username: TylerDurdenDev
Password: TylerDurdenDev@2011
```

## SSH

SSH is a separate protocol, so an SSH client still needs a host, port and username/password.

Built-in SSH identity:

```text
Username: TylerDurdenDev
Password: TylerDurdenDev@2011
Container port: 2222
```

Railway must provide TCP Proxy access for the public SSH host/port. The public host and port are generated by Railway, not by this repository.

## Persistence

Attach a Railway Volume and mount it at:

```text
/data
```

Use `/data` for projects and files that should survive supported restarts/redeploys.

## Important security note

The browser terminal is protected with HTTP basic auth, so the public URL alone is not enough. The built-in credentials (`TylerDurdenDev` / `TylerDurdenDev@2011`) are shipped in the repository and are therefore public — change them in `scripts/entrypoint.sh` before using this service for private or sensitive workloads.

## Platform limitation

This is a Linux container on Railway, not an unrestricted traditional VPS. Railway controls the container runtime, networking, resources and platform policies. It should not be treated as a machine with unrestricted kernel-level access, privileged Docker access, GPU access or arbitrary inbound networking.
